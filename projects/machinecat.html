MachineCat — AI Robotic Companion

As the sole software developer of a hackathon team, built the complete software stack of an award-winning LLM-driven robotic companion: personality engine, multi-protocol device communication, and a Web3 edition.

Published May 24, 2026 • Event May 6, 2026
Node.js Koa React DDD LLM MQTT Solana

What it is

MachineCat is an AI-powered robotic companion developed for hackathon competitions. Two versions exist on two branches: a Web2 hackathon edition and a Web3 / OKX hackathon edition.

My role: Independent Software Developer / Software Lead — every commit in both branches is mine. Teammates covered visual artwork, video production, concept development, and pitching — and brought the robot itself, an off-the-shelf hardware kit. All software — frontend application, backend, deployment, integrations — was designed and implemented by me alone, and the device was driven through the communication interfaces it exposed (HTTP, WebSocket, Bluetooth).

Web2 edition — core engineering

The backend is organized with DDD + hexagonal architecture, with bounded contexts under the server core:

  • robot-personality — persona / breed / trait domain
  • ai-interaction — LLM prompt building, response parsing, action choreography
  • robot-control — robot aggregate plus HTTP / WebSocket / Bluetooth connectors
  • intimacy — LLM-based intimacy analysis and persistence
  • conversation — conversation tracking and anti-sedentary behavior

Key implementation decisions:

  • Structured LLM output drives a physical device. The prompt forces the model to return {text, actions[]} — actions drive robot movement over HTTP, WebSocket, or Bluetooth connectors. Free-text parsing was never an option when the “user” has motors.
  • LLM as analyzer. The intimacy system asks the LLM to score each exchange (−3..+3 delta plus per-trait adjustments), clamps and persists results for personality evolution.
  • Hardware-free development. A virtual robot simulator speaks the same three protocols, so the whole stack runs locally without a physical device.
  • Speech input via audio upload endpoint; JWT + bcrypt authentication.

Stack: JavaScript (React 19), Zustand, Node.js, Koa, MongoDB (Mongoose), ws, JWT, bcrypt, winston.

Web3 edition — integration breadth

Built on the same foundation, adds:

  • Solana integration: on-chain robot state via @solana/web3.js + Anchor PDAs (initialize / update_state / complete_quest), with a mock/real fallback so the demo never dies when RPC is down.
  • Cross-chain payments: LI.FI quotes, MagicBlock, x402 — again with mock/real switches.
  • OKX DeFi data via HMAC-SHA256 signed API requests; OKX / Phantom wallet connection.
  • Strategy-based authentication: email, Google OAuth, and Solana wallet-signature auth behind one auth manager.
  • Device infrastructure: standalone MQTT broker service + device management API, orchestrated with Docker Compose (MongoDB, Redis, MQTT, Ollama, server, app, nginx) and deployed to Solana Devnet with a live demo on Vercel.

What it demonstrates

  • End-to-end independent delivery: design → code → Docker Compose → tunnel → live demo.
  • DDD / hexagonal boundaries applied in a real working project, not a toy example.
  • LLM application engineering: structured output, persona prompts, degradation paths.
  • Integration breadth: Solana, LI.FI, OKX, x402, MQTT, multi-protocol device communication.
  • Honest AI-assisted attribution inside a disciplined process.
